# 办案

一个律师、一个账号、一件案子一条记录。产品规则以《agent-v3开发计划》为准。开发按《开发指导》逐条走。

```bash
npm run dev
```

浏览器打开 http://localhost:3010 。这一版用 3010，避免和上一版的 3000 抢端口。

只读写 `data/v3.sqlite`。不打开、不迁移 `data/law.sqlite`。库启动时是空的，不写入旧案子。材料原件放在 `data/v3-files/`。

## 第 1 条

开一张空卡，点明客户并创建。也可以把文本丢进来或贴进来，只用来预填。

记录上留下一件草稿：客户写入 `clients`，案子写入 `matters`，当事人按人分行写入 `parties`。对方不收成一格。状态是草稿。不调用模型，不接企查查，不把文本收成材料。

律师怎么点：

- 工作台点「开一张空卡」。没有案子时，工作台写「还没有案子。」
- 不丢文本也能创建。案件名称可以空着，空着就用客户的名称。案由、请求、基本事实、对方、办案机关都可以先空着。
- 客户要自己点明，或在客户一栏写下。不点明就创建，页面写「请点明谁是客户。」案子不会出现。
- 把一份 `.txt` 丢进来，或把文本贴进框里再点「按这段预填」。读出的每个人单独一行，诉讼地位和统一社会信用代码写在这一行上。创建前可以改。原告、被告人不会变成客户。
- 一行里用顿号分开的人，各占一行。读不出当事人、案由或请求，这些栏空着。
- 点「创建」之后打开这件草稿。客户、对方、办案机关分三列。请求记在委托事项里。刷新后还在。工作台也能打开。

接口：

- `POST /api/intake/read`：一份 `.txt`，或 JSON `{ "text": "..." }`。只返回预填，不写库。不是文本、空文本，分别拒绝。
- `POST /api/matters`：点明了客户才建草稿。没点明返回 400，「请点明谁是客户。」当事人如果收成一串字，返回 400，「当事人要每人一行。」
- `GET /api/matters`
- `GET /api/matters/:id`

可以拆下：

- 表：`clients`、`matters`、`parties`。`lib/db.ts` 把这一版要用的表一次建好，这一步只写上面三张。
- 文件：`lib/intake.ts` 只读文本。`lib/matters.ts` 只读写记录。
- 接口：`app/api/intake/read/`、`app/api/matters/`。
- 面板：`components/create-card.tsx`。去掉预填之后，空卡创建仍然成立。

### 测试

浏览器和接口都走过。库里留着两件草稿。

- 空卡不填客户就点创建，页面写「请点明谁是客户。」没有新案子。
- 只点明客户「李某」，写下案由和请求。建成草稿，名称用了客户名。委托事项是「判令支付租金。」对方和办案机关空着。刷新后还在，工作台能打开。
- 贴进一份起诉状。预填出甲建设有限公司、乙置业有限公司、丙贸易有限公司三行，客户一栏是空的，原告没有被点明。杭州市西湖区人民法院在办案机关。案由和请求已填上。此时还没有新案子。
- 点明乙置业有限公司后创建。草稿里客户是乙置业，诉讼地位是被告。对方是甲建设和丙贸易，各占一行，甲建设带统一社会信用代码。办案机关单独一列。
- 贴进一段闲聊。页面写没有读出当事人、案由或请求，卡片空着。
- 接口：不带客户返回 400。当事人写成「乙、丙」一串也返回 400，案子数不变。空读返回空列表。不是 `.txt` 的文件返回 400。读和创建都不写入材料。`data/law.sqlite` 没有出现。

响应式：

- 宽屏 1280：概览上客户、对方、办案机关横排，标题和三列都在屏内。工作台和创建卡没有横向溢出。
- 窄屏 390：三列改成上下排列。创建卡上的输入和按钮都在屏内。页面宽度 390，没有横向溢出。

## 第 2 条

放入一份文字材料，并确认读出的文字。

记录上留下原件和两段文字。原件在 `data/v3-files/` 这件案子的目录下。库里 `materials.read_text` 是机器读出的副本，先标待核对。律师确认后，`usable_text` 成为可用文字，`text_status` 改为可用文字。确认不改基本事实，也不改案子状态。这一步只收 `.txt`。照片、扫描件和录音先不放进来。

律师怎么点：

- 打开草稿，点「材料」。
- 选择一份 `.txt`，点「放入材料」。没选文件时，页面写「请选择一份材料。」
- 放进去之后，材料上写待核对，旁边是读出的文字。可以改。
- 点「确认文字」。材料改成可用文字。改过的字留下；机器读出的原文停在旁边。
- 可以打开原件。刷新后，状态和两段文字都还在。概览上也看得到这份材料的状态。

接口：

- `POST /api/matters/:id/materials`：放入一份 `.txt`。不是文本、空文本，分别拒绝。同名返回 409，「本案已经有同名材料。」
- `POST /api/matters/:id/materials/:materialId/confirm`：提交确认后的文字。空白返回 400，「请确认读出的文字。」已经确认再点，返回 409，「这份材料已经确认。」
- `GET /api/matters/:id/materials`
- `GET /api/matters/:id/materials/:materialId/file`：打开原件。

可以拆下：

- 表：`materials`。原件目录 `data/v3-files/`。
- 文件：`lib/materials.ts`。
- 接口：`app/api/matters/[id]/materials/`。
- 面板：`components/material-desk.tsx`。去掉这一块，空卡创建仍然成立。

### 测试

接口走完一份材料的放入、待核对、改字确认、可用文字。确认后基本事实没变，再确认返回 409。同名、空文件、不是 `.txt`，都拒绝。没点明客户仍然不能创建。

浏览器用李某这件草稿走过。没选文件就点放入，页面写「请选择一份材料。」房屋租赁合同.txt 放进本案后，材料页写待核对，文字是「承租人李某。租金未付。」在页面上改成「租金已经付清。」再点确认。页面写可用文字，机器读出仍是「租金未付。」刷新后还在。概览上案由、委托事项没变，基本事实仍是空的，材料状态是可用文字。案子仍是草稿。乙置业那件草稿没有放入材料。

响应式：

- 宽屏 1280：材料页没有横向溢出。
- 窄屏 390：文件名、待核对或可用文字、确认和原件都在屏内。页面宽度 390，没有横向溢出。

## 第 3 条

填写诉讼地位，并把第三列当作办案机关。

记录上，诉讼地位写在 `parties.position`。办案机关仍是单独一行，`role` 是 organ。种类写在 `matters.category`，只能空着，或写民事、刑事、行政诉讼、非诉专项、法律顾问、其他。改种类、改诉讼地位、再加一位对方或办案机关，都不改案子状态，也不改基本事实。客户仍只在创建时点明。

律师怎么点：

- 打开草稿的概览。客户、对方、办案机关三列一直在。种类换成刑事或行政诉讼，这一页不换。
- 种类选一项，点「记下种类」。标题旁变成「刑事 · 草稿」这一类。选「还没写」，旁边只留下状态。
- 已有的人，改诉讼地位后点「记下」。刑事的被告人可以写在客户这一行上，这一行仍是客户。
- 对方一列可以再加一位。名称里有顿号，页面写「请每人一行。」
- 第三列写下办案机关的名称和诉讼地位，点「记下办案机关」。复议机关、检察院、公安机关写在这一列。
- 客户一列没有添人的地方。

接口：

- `POST /api/matters/:id/category`：JSON `{ "category": "刑事" }`。不在清单里返回 400，「种类要写在清单里。」
- `POST /api/matters/:id/parties`：JSON `{ "role": "organ", "name": "杭州市人民政府", "position": "复议机关" }`。`role` 只能是对方或办案机关。写成客户返回 400，「客户要在创建时点明。」名称里有顿号返回 400，「请每人一行。」
- `POST /api/matters/:id/parties/:partyId`：JSON `{ "position": "被告人" }`。只改诉讼地位，不改这一行是客户、对方还是办案机关。

可以拆下：

- 表：`parties.position`、`matters.category`。
- 文件：`lib/parties.ts` 读写当事人。`lib/categories.ts` 是种类清单，页面和接口共用。
- 接口：`app/api/matters/[id]/category/`、`app/api/matters/[id]/parties/`。
- 面板：`components/overview-editor.tsx`。去掉这一块，空卡创建和材料确认仍然成立。

### 测试

接口用一件临时草稿走过。种类写成「专利」返回 400。按客户再加人返回 400，「客户要在创建时点明。」客户的诉讼地位改成被告人，这一行仍是客户。办案机关「杭州市人民政府」、诉讼地位「复议机关」单独一行。案子仍是草稿，基本事实没变，材料数是 0。测完删掉这件草稿。没点明客户仍然不能创建。第 2 条的材料接口再走一遍，仍然通过。`data/law.sqlite` 没有出现。

浏览器用乙置业这件草稿走过。种类先记成刑事，三列还在。客户乙置业有限公司的诉讼地位改成被告人，点记下。再把种类改成行政诉讼，页面仍是这三列。办案机关一列加上杭州市人民政府，诉讼地位是复议机关。原来的杭州市西湖区人民法院还在，单独一行。刷新后都在。案由、委托事项没变，基本事实仍是空的，本案没有材料，案子仍是草稿。

李某那件草稿没有被改。种类还没写，状态仍是草稿，基本事实仍空，房屋租赁合同.txt 仍是可用文字。工作台上两件案子都在，对方和办案机关每人一行。

响应式：

- 宽屏 1280：概览上三列横排。概览和工作台都没有横向溢出。
- 窄屏 390：三列改成上下排列。概览、材料页和工作台的页面宽度都是 390，没有横向溢出。

## 第 4 条

记下一条只有名称和到期日的待办，并确认。记下实收。

记录上，待办写入 `tasks`。名称和到期日先留下，`confirmed_at` 为空，这时是待确认。律师确认后写入确认时间，才出现在工作台。实收写在 `matters.fee_received`，以元计，两位小数。空着表示还没记。不记应收。不推算答辩、上诉、保全，也不计算时效、利息、受理费。确认待办和记下实收都不改案子状态，也不改基本事实。

律师怎么点：

- 打开草稿，点「待办」。
- 写下名称和到期日，点「记下」。没写名称，页面写「请写下名称。」没写日期，页面写「请写下到期日。」
- 记下之后，这条待办写待确认，工作台的到期里还没有它。
- 点「确认」。这条待办改成已确认。刷新后还在。工作台的到期里能看见名称、日期和案子。九十天内或已经过期的，同时出现在提示里。已经过期的标已过期。
- 实收写下金额，点「记下实收」。写到分。不是金额，页面写「金额写到分。」
- 工作台上面是提示、到期和实收。实收按案子列出，并给出合计。还没记的案子写「还没记」。

接口：

- `POST /api/matters/:id/tasks`：JSON `{ "name": "提交证据", "dueOn": "2026-11-20" }`。先待确认。
- `POST /api/matters/:id/tasks/:taskId/confirm`：确认。已经确认再点，返回 409，「这条待办已经确认。」
- `GET /api/matters/:id/tasks`
- `POST /api/matters/:id/fee`：JSON `{ "amount": "3500.50" }`。空字符串表示还没记。
- `GET /api/workbench`：提示、到期和实收。未确认的待办不在里面。

可以拆下：

- 表：`tasks`、`matters.fee_received`。
- 文件：`lib/tasks.ts`。实收写在 `lib/matters.ts`。
- 接口：`app/api/matters/[id]/tasks/`、`app/api/matters/[id]/fee/`、`app/api/workbench/`。
- 面板：`components/task-desk.tsx`。去掉这一块，空卡、材料确认和诉讼地位仍然成立。

## 第 5 条

在工作台新开一段对话，选问答，再追问一句。

记录上，一段对话写入 `threads`，`matter_id` 为空，所以先不挂案子。每一轮写入 `messages`：律师的话 `role` 是 lawyer，回答是 model，`mode` 是问答。问法条或案例时，先不叫模型。律师点仍要问答之后，回答才写入，法条和案号标未经核对。这段对话不改待办、实收、基本事实和材料。

律师怎么点：

- 工作台的「对话」里，这一轮选问答，写下要问的话，点「问」。
- 打开这段对话。上面是已经问过的。再写一句，点「问」，就是接着问。刷新后都还在。回到工作台，对话列表里能找回。
- 问到法条或案例，页面写「这是在问法条或案例。改去直接检索。仍要问答，点「仍要问答」。」点「仍要问答」后，回答里的法条和案号带未经核对。
- 选直接检索再点「问」，页面写「直接检索还不查。」不会新开对话，也不入库。

接口：

- `POST /api/threads`：JSON `{ "mode": "问答", "text": "..." }`。新开一段，不挂案子。
- `POST /api/threads/:id/messages`：接着问。JSON `{ "mode": "问答", "insist": true }` 表示仍要问答。
- `GET /api/threads`
- `GET /api/threads/:id`
- 没写要问的话，返回 400，「请写下要问的话。」选直接检索，返回 400，「直接检索还不查。」

可以拆下：

- 表：`threads`、`messages`。
- 文件：`lib/threads.ts` 读写对话。`lib/model.ts` 只调用模型，不读库，不查北大法宝。
- 接口：`app/api/threads/`。
- 面板：`components/thread-composer.tsx`。去掉这一块，空卡、材料、诉讼地位、待办和实收仍然成立。

### 测试

接口用一段临时对话走过。空话拒绝。直接检索拒绝，并且没有新对话。问答先问一句，再追问一句，四条消息都在，`matter_id` 为空。接着问《民法典》第五百七十七条和案例，先停在提示，还没有新的回答。点仍要问答后，回答写入，正文里有未经核对。测完删掉这段对话。李某的状态、基本事实、实收、可用文字和「提交证据」都没变。`data/law.sqlite` 没有出现。

浏览器用工作台走过。选直接检索，写下「查一下合同」，点问，页面写「直接检索还不查。」对话列表仍是空的。改回问答，问「承租人说租金已经付清。接下来先核对哪一版文字？」打开这段对话，页面写还没有挂到案子上。再问「如果机器读出的是未付，律师改成了付清，先信哪一版？」两问两答都在。刷新后还在。再问「《民法典》第五百七十七条怎么规定？有没有相近案例？」先出现改去直接检索的提示，这一问下面还没有回答。点「仍要问答」后，回答里《民法典》第五百七十七条标了未经核对。回到工作台，对话列表能打开这段。提交证据和实收合计 3500.50 元还在。李某仍是草稿。

响应式：

- 宽屏 1280：工作台和对话页没有横向溢出。
- 窄屏 390：问答、直接检索、输入和问都在屏内。工作台和对话页的页面宽度都是 390，没有横向溢出。

## 第 6 条

把这段对话建成案子，并点明客户。

记录上，点「建成案子」并点明客户后，新开一件草稿，只把 `threads.matter_id` 补上这段对话。对话里看得出的当事人、案由、基本事实写成待确认：`messages.proposal_kind`、`proposal_body`，`accepted_at` 为空。点「留下」才把这一项写入案子。不点的话，案子仍是空卡，加上这段对话。状态仍是草稿。客户要单独点明，看出来的人不会变成客户。每个人仍是一行。

律师怎么点：

- 打开一段还没挂案子的对话。写下客户，点「建成案子」。不写客户，页面写「请点明谁是客户。」
- 建成后，页面写已挂到这件草稿。看出的当事人、案由、基本事实停在待确认。
- 先打开这件草稿：案由、基本事实还没写，对方还没写，只有点明的那位客户。状态是草稿。
- 只点某一项的「留下」。这一项写入，另外两项仍是待确认。

## 第 16 条

在中栏让 agent 分析一个法律问题，或写成一份文书。有必要就查北大法宝。律师也可以写上要查法宝，或不查法宝。

没有勾选出处时，写成文书或分析法律问题会先检索。候选出现在右栏。没勾的不入库。勾上的原文快照写入出处，这一问成为焦点。已经有勾选出处时，不查法宝就只根据这些出处分析和成文，不再检索。要查法宝就再检索，仍不把没勾的写入。没有出处又指定不查，回答写「没有勾选出处。这一问先不写结论，也不把法条和案号写成依据。」不写成文。

文书和判断只用勾上的法条和案例。它不自己选定诉请、胜负或文书结构。文书种类仍由律师填写。留下的是新的文书版本。状态、客户、可用文字、实收、归档都不由它改。归档后分析或成文返回 409，「归档后只供查阅。」

律师怎么点：

- 中栏保持问答。写「写成一份文书：……」。还没有出处时，右栏换成候选。勾一条，点「收下勾选的」。没勾的还在候选里，不进已收下的出处。
- 再写「分析法律问题：……。不查法宝。」回答只根据已勾选的出处。右栏的检索句不变，没勾的仍不入库。
- 再写「写成一份文书：……。不查法宝。」稿子出现在对话旁。文书种类自己写，例如情况说明。改过正文再点「留下」。记下的是这一版，状态仍是草稿。

接口仍是原来的问答、勾选和留下：

- `POST /api/matters/:id/ask`，`{ "mode": "问答", "text": "..." }`。写成一份文书，或分析法律问题，才走这一步。要查法宝、不查法宝写在这句话里。
- `GET /api/threads/:id/candidates` 看候选。候选不入库。
- `POST /api/threads/:id/candidates/accept` 只收下勾上的。
- `POST /api/matters/:id/drafts` 留下文书版本。种类和正文都由律师提交。

可以拆下：

- 文件：`lib/legal-turn.ts` 认出分析和成文，以及查或不查。`lib/threads.ts` 在没有出处时检索，有出处时只把勾上的交给模型。
- 直接检索和分析成文的单选仍在。工作台的版面没有改。
